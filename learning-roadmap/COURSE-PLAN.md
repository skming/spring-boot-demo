# DB Lab 后端与数据库教学路线

更新日期：2026-10-22。

## 目标与唯一课程顺序

目标见 [MISSION](../MISSION.md)：独立修改观影项目后端，能解释请求、业务、持久化与数据库的完整过程，并验证正常、失败和授权路径。

**正式课程顺序以 `/learn` 为准，单一内容来源为 [curriculum.ts](../frontend/src/features/learn/curriculum.ts)。** 本文说明阶段设计和验收，不维护另一套编号课程。README 提供入口，backend/database Markdown 作为查阅参考，页面操作说明不作为必学课程。

面向熟悉TypeScript、HTTP接口调用与日常开发工具，但尚未系统学习Java、Spring和数据库的前端开发者。目标是能够在现有项目中完成小型后端需求，不等同具备生产后端独立交付能力。

目前有9个阶段、32节快速开发主线、10节深入理解专题。目录分区展示，主线的上一课/下一课仅经过主线；专题提供独立的前后导航，以及沿前置关系计算的主线继续入口。专题不成为主线的前置条件。课程使用稳定的语义ID，显示序号不承担分组或路由规则。

## 学习前提与实验环境

- 先按 [START-HERE](START-HERE.md) 启动并认识项目；不要求在第一课就理解全部框架注解。
- 默认 SQLite，无需 Docker。实际教学业务库有 users、movies、watch_records、operation_logs 四张表。
- 课内 SQL 使用每用户独立临时样本库，初始为 2 个合成用户、3 部电影、3 次观看，不包含真实凭据。
- `/lab` 操作实际教学业务库；不要与课内临时库混用。课程写入练习优先在隔离样本中执行。
- Java 基础只补当前项目所需的对象、字段、方法、集合、接口、异常与框架调用区别，不扩展成完整语言课程。
- 页面用于操作与核对结果，不教授界面实现。无任务挑战、积分、排名或自动“已掌握”状态。

## 九阶段主线

| 阶段 | 课程范围 | 应具备的能力 | 关键检查 |
|---|---|---|---|
| 1. 项目、数据与 Java 基础 | 启动、Maven目标、配置/profile、断点与异常链、数据模型、Java/TypeScript差异 | 定位请求栈，区分内存状态与数据库 | 可空包装类型、equals、record、Optional、同步调用 |
| 2. HTTP 与接口契约 | HTTP、DTO、校验、第一次实际修改、统一响应 | 第9课开始修改备注校验，读懂准备→调用→断言 | 800/801/null、400与失败不写入 |
| 3. Spring 与 JPA 基础 | @Service/@Bean、构造器注入、分层、Entity、Repository | 找到依赖来源与持久化入口 | 区分Bean、DTO、Entity和getter/setter |
| 4. SQL 查询基础 | SELECT/NULL、WHERE/排序/LIMIT | 查询核对接口结果，写入与约束按需深入 | 引号、用户范围、空结果 |
| 5. 电影 CRUD 与分页 | 查询与转换、分页契约、新增、受管更新、删除 | 追踪完整用例，明确List与Page不同 | HTTP与SQL核对同一ID；日志分页；观看不被覆盖 |
| 6. 登录与数据归属 | 密码校验/JWT、CurrentUserService、ownerId、资源授权 | 区分“是谁”和“能操作什么” | 两用户交叉 GET/PUT/DELETE；不能靠请求体伪造归属 |
| 7. 多次观看与关联查询 | 一对多与删除、观看CRUD、JOIN/ON/WHERE | 解释子记录生命周期与关联多行 | LEFT/INNER JOIN、空关联、归属 |
| 8. 事务与一致性 | flush/commit/rollback、基本代理边界、REQUIRED | 必要审计与电影一起成功或失败 | flush后回滚、事务外核对最终数据 |
| 9. 审计与独立开发 | 快照、发行年份完整示范、原文片名独立修改 | 贯通DTO、实体、表结构、Service、查询、审计和测试 | 边界、读写一致、越权与审计失败回滚 |

### 前置知识与逐步深入

- 先认识一部电影对应多次观看，再进入 SQL 或 JPA 的关系细节。
- 主线先用SELECT核对数据；INSERT、UPDATE、DELETE与约束在专题中先正常写入再观察拒绝，不强制学完全部SQL才修改接口。
- JOIN 课不先塞入 GROUP BY；观察关联产生的行之后，再学习聚合统计。
- 第一次业务写入仅说明“必要写入一起完成”的事务边界；提交、代理与传播在事务阶段系统展开。
- 早期以已登录身份作为接口操作前提，CRUD 后再解释身份来源，不要求一开始实现 JWT。
- 第9课实际修改MovieRequest.notes的校验，先补800/801/null边界测试，再修改注解；不改实体列，不截断历史数据。完整PUT提交超长历史备注会被新规则拒绝，需要明确说明这一接口行为变化。
- HTTP熟悉的读者可核对项目契约后直接进入首次修改；授权、校验和失败回滚不得因为“会调用接口”而省略。
- 测试贯穿全程；主线末尾在已有示范基础上完成不同字段需求，不重复首次校验练习。

### 按需深入专题

集合与remove；SQL写入/主外键/影响0行；聚合与NULL统计；genres转换器；事务代理与同类调用；catch与rollback-only；受检异常与rollbackFor；REQUIRES_NEW。除最后一项，其他专题使用默认SQLite环境即可。移出主线不等于不重要，遇到相关开发问题时回查。

### 专题：REQUIRES_NEW 独立提交

入口为 `/learn/requires-new`，课程目录及相关 REQUIRED/受检异常课提供链接。它是唯一需要Docker/MySQL的专题，不阻塞默认SQLite主线。

实验先在外层写入并 flush，再由独立 Bean 提交另一笔事务，最后回滚外层。事务外应只保留独立电影及相应审计。无环境时允许跳过，不把测试跳过记作实验通过。不以调整写入顺序规避 SQLite 单写者限制来冒充独立提交证明。

## 每课固定结构

1. **前置课程与一个问题**：链接到真正用到的基础，不按显示序号推算单元。
2. **必要概念与真实代码**：标识源码节选或教学示例；片段省略上下文时明确说明。
3. **先预测**：写出或口述结果及理由，再使用选择题辅助核对。
4. **动手操作**：只改变一个字段、SQL 条件或调用路径，不同时引入多处变化。
5. **核对证据**：明确行数、状态、字段或事务外数据库断言；选择题不能替代实际修改。

答案绑定课程内的稳定选项 ID，不引用显示位置或按课次奇偶推算。调整选项顺序时 ID 随选项保留；题目内容或答案更新后重置旧作答。选项 ID 不标记正确性，页面不累计分数或上传答案。

## 示例与路线检查

- 所有课都有有效源码入口、问题、预测、操作、结果与官方参考，不引用界面实现作为课程源码。
- 路线无遗漏、无重复；前置存在且排在前面，主线不能依赖专题；默认导航不进入专题。第9课必须是首次实际修改。
- 标为源码节选的代码与源文件进行规范化空白后的片段匹配，不仅检查存在一个方法名。
- 所有可执行 SQL 示例均在临时 SQLite 中实际运行，按语义 ID 断言结果，而不是依赖会变化的课次编号。
- 成功 INSERT、UPDATE、DELETE 必须验证实际数据；重复主键、外键失败、影响 0 行、空查询、LEFT JOIN 和 NULL 聚合均有检查。
- 课程导航、前置链接、动手步骤和选修说明用静态渲染检查。静态渲染不能代表浏览器的滚动、焦点或 Monaco 实际挂载验收。
- 业务代码仍由现有 JUnit、MockMvc 与真实数据库集成测试验证。自动检查不等于学习者已掌握。

## 独立修改的完成标准

先阅读“开发示范：新增发行年份”：releaseYear允许null或1888–2100。示范贯通请求/响应DTO、实体字段与手写getter、构造器/update、Service映射、保留ownerId的查询、审计快照和测试。**这是待实现需求，不是当前API已经提供的字段。**

随后独立实现不同需求：originalTitle可选、最大100字符、空白规范化为null，新增/修改/查询/列表/审计返回一致，不覆盖观看历史：

- 说明请求/响应DTO、实体列、构造器、update、Service与审计受影响位置，先写测试再实现。
- 覆盖100/101字符、null、空白、读写往返、他人数据与审计失败后原数据不变。
- 提供实际代码差异和测试结果，解释为什么修改在这一层。
- 区分局部单元测试、HTTP 契约断言与事务外数据库证据。
- 在 backend 运行相关测试及 `./mvnw -o test`；无 Docker 的 MySQL 测试如实记为跳过。

以上新增字段只能在独立练习副本和一次性测试库实施。SQLite的IF NOT EXISTS不会自动给旧表加列；已应用的MySQL Flyway V1也不能直接修改作升级脚本。已有库需要另行确认迁移与恢复方案。本轮只更新课程，不实施这些业务字段，不修改schema或数据。
